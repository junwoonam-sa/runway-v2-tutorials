# 3-2. 상태 확인

챗봇 화면을 열고, 무엇이 준비됐는지 확인합니다.

걸리는 시간 10분.

---

## 열어 보기

3-1에서 외부 접근을 켜지 않았으므로 아직 인터넷 주소가 없습니다.
잠깐 연결해서 보는 방법이 있습니다.

Code Server의 터미널에서 (`<프로젝트 ID>` 만 바꾸세요):

```bash
kubectl -n <프로젝트 ID> port-forward svc/llm-chat 8080:80
```

이 명령은 **켜 둔 채로 두어야 합니다.** 끄면 연결이 끊깁니다.

그 상태에서 Code Server 화면의 **PORTS** 탭으로 가서 `8080` 포트를 엽니다.
새 탭에 챗봇 화면이 뜹니다.

---

## 상태 배지 읽기

화면 오른쪽 위에 **상태 배지**가 있습니다. 이 챗봇의 안내 데스크입니다.

| 배지 | 뜻 |
|---|---|
| 🟢 **준비됨** | 전부 정상입니다 |
| 🟡 **확인 필요** | 대화는 되지만 일부 기능이 꺼져 있습니다 |
| 🔴 **문제 있음** | 대화를 시작할 수 없습니다 |

**문제가 있으면 화면이 저절로 펼쳐집니다.** 무엇이 잘못됐는지와 **어떻게 고치는지**가
항목마다 적혀 있습니다. 로그를 볼 필요가 없습니다.

전부 정상이면 이렇게 보입니다.

```
  ● LLM API 키          키가 주입되어 있습니다.
  ● LLM 게이트웨이      연결됨. 모델 2개가 있습니다.
  ● 사용 중인 모델      qwen2-5-0-5b-instruct (게이트웨이 목록에서 자동으로 골랐습니다)
  ● 도구 서버 (MCP)     도구 5개가 준비되어 있습니다.
  ● 벡터 DB (문서 검색) 연결됨. 컬렉션 tutorial-docs 에 조각 0개가 있습니다. 아직 올린 문서가 없습니다.
  ● 임베딩              게이트웨이 계산합니다.
```

---

## 각 항목이 뜻하는 것

| 항목 | 무엇을 보는가 | 문제면 |
|---|---|---|
| LLM API 키 | OpenBao에서 키가 왔는가 | 0-2와 3-1의 엔진·시크릿 이름 확인 |
| LLM 게이트웨이 | AI 서비스에 연결되는가 | `runway.llm.baseUrl` 확인 |
| 사용 중인 모델 | 어떤 AI를 쓰고 있는가 | 게이트웨이에 모델이 없는 경우 |
| 도구 서버 (MCP) | 문서 검색 도구가 준비됐는가 | 앱 내부 문제 — 메시지를 그대로 문의하세요 |
| 벡터 DB | 문서 창고에 연결되는가 | 창고 주소 확인 (2-2) |
| 임베딩 | 문서를 어떻게 벡터로 바꾸는가 | 게이트웨이/앱 중 어디서 계산하는지 표시 |

**"조각 0개"는 정상입니다.** 아직 문서를 안 올렸으니까요. 4단계에서 올립니다.

---

## 자주 나오는 두 가지

### 🟡 벡터 DB — 설정되지 않았습니다

3-1의 `runway.vector.url` 을 안 넣었거나 `enabled: false` 인 경우입니다.
대화는 되지만 문서 기능이 없습니다. YAML을 고치고 **다시 배포**하세요.

### 🔴 벡터 DB — 연결하지 못했습니다

주소는 넣었는데 통하지 않는 경우입니다. 2-2의 확인을 다시 해 보세요.
Qdrant의 ID와 프로젝트 ID가 주소에 정확히 들어갔는지가 대부분입니다.

---

## 여기까지 되면 성공

- [ ] 챗봇 화면이 열린다
- [ ] 상태 배지가 🟢 **준비됨** 이다
- [ ] "사용 중인 모델" 항목에 모델 이름이 보인다

🟡 가 하나 있어도 다음으로 넘어갈 수 있습니다 — 대화는 됩니다.
🔴 라면 해당 항목의 안내를 먼저 따르세요.
