# 애플리케이션 알고가기

읽는 데 5분. 여기 세 가지를 알고 가면 뒤에서 막히는 일이 크게 줄어듭니다.

---

## 1. 프로젝트 이름 하나가 여러 곳에서 똑같이 쓰입니다

**프로젝트**는 내 작업이 담기는 칸입니다. 프로젝트를 만들면 이름이 같은 것이 여러 개
생깁니다 — 문서 창고 주소를 만들 때도, OpenBao에 로그인할 때도 이 이름이 들어갑니다.

그래서 0단계에서 **프로젝트 ID를 정확히 적어 두는 것**부터 시작합니다. 대소문자와
하이픈까지 그대로요.

---

## 2. 애플리케이션은 "Helm 차트"를 설치하는 것입니다

Runway에서 무언가를 배포한다는 것은 **차트(chart)** 를 고르는 일입니다.
정확히는 **Helm 차트**입니다 — 화면에도 그렇게 쓰여 있습니다.

| 화면에서 보게 될 말 | 어디서 |
|---|---|
| **Helm 리포지토리 URL** | 3-1, 주소를 등록하는 칸 |
| **차트 / 차트 버전** | 3-1, 드롭다운 |
| **헬름 차트 (values.yaml)** | 3-1, 값을 고치는 영역 |

**Helm이 무엇인지 몰라도 이 튜토리얼은 끝까지 갈 수 있습니다.** 다만 화면에 그
단어가 나오니, 무슨 뜻인지만 알고 가면 됩니다.

- **차트** = "이 프로그램을 이렇게 실행해라"가 적힌 설치 설명서 한 묶음
- **values.yaml** = 그 설명서의 **빈칸**. 사람마다 다른 값(내 프로젝트 이름, 내 볼륨
  이름)을 여기 채웁니다
- **Helm 리포지토리** = 차트들이 모여 있는 창고 주소

3단계에서 하는 일이 정확히 이겁니다 — **창고 주소를 등록하고, 그 안의 차트를 고르고,
빈칸을 채우는 것.**

차트는 두 가지 방식으로 옵니다.

| | 예 | 이 튜토리얼에서 |
|---|---|---|
| Runway가 기본 제공 | Code Server, Qdrant | 1·2단계 — 목록에서 고르기만 합니다 |
| 리포지토리를 등록해서 가져오기 | 우리 챗봇 | 3단계 — 창고 주소를 한 번 등록합니다 |

앞의 둘은 Runway가 창고를 이미 알고 있어서 목록에 바로 나타납니다. 우리 챗봇은
Runway가 모르는 창고에 있으므로 주소를 알려 줘야 합니다.

> **Runway는 소스 코드에서 자동으로 만들어 주지 않습니다.** git 저장소 주소를
> 넣는 것이 아니라, **이미 만들어져 창고에 올라간 차트**를 가져옵니다. 그래서
> 3단계에서 넣는 주소는 소스 저장소 주소가 아닙니다.

---

## 3. 만드는 것과 배포하는 것은 다릅니다

**이게 가장 자주 걸리는 지점입니다.**

애플리케이션 생성 폼을 채우고 **생성**을 누르면, 목록에 이름이 나타납니다.
하지만 **아직 아무것도 실행되지 않았습니다.** 설정만 저장된 상태입니다.

상세 화면으로 들어가서 **배포(Deploy)** 를 눌러야 실제로 뜹니다.

```
  [생성] ──▶ 목록에 나타남 (아직 안 돎)
                    │
                    ▼
            상세 화면 열기
                    │
                    ▼
            [배포] ──▶ 실행됨 ──▶ 상태 Healthy
```

"만들었는데 아무 일도 안 일어나요"의 대부분이 배포 버튼을 안 누른 것입니다.
이 튜토리얼에서 애플리케이션을 세 번 만드는데, **세 번 다** 이 순서입니다.

설정을 고쳤을 때도 마찬가지입니다 — 고친 뒤 **다시 배포**해야 반영됩니다.

---

## 화면에서 자주 보게 될 상태

| 상태 | 뜻 |
|---|---|
| `Healthy` | 정상적으로 돌고 있습니다 |
| `Progressing` | 뜨는 중입니다. 1~2분 기다려 보세요 |
| `Degraded` | 문제가 생겼습니다. 상세 화면에서 이유를 볼 수 있습니다 |
| `terminated` | 만들었지만 아직 배포하지 않았습니다 |
