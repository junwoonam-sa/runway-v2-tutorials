# 0-2. OpenBao 시크릿 등록

방금 만든 키를 OpenBao에 저장합니다.

걸리는 시간 10분 · 전부 화면에서 클릭하는 작업입니다.

---

## 왜 OpenBao에 넣나

키를 챗봇 설정 칸에 그냥 적어 넣을 수도 있습니다. 하지만 그러면 그 애플리케이션을
볼 수 있는 사람 모두가 키를 보게 됩니다.

**OpenBao**는 Runway가 제공하는 시크릿 저장소입니다. 여기에 넣으면 챗봇이 실행되는 순간에만
꺼내 쓰고, 설정 화면 어디에도 값이 남지 않습니다.

```
  OpenBao  ──실행 시점에 전달──▶  챗봇
        ▲
        └─ 값은 여기에만 있습니다. 설정에도, 이미지에도 없습니다.
```

1단계에서 이게 실제로 전달되는 것을 **눈으로 확인**하게 됩니다.

---

## OpenBao 열기

콘솔 → **Built-in Apps** → **OpenBao** 카드를 클릭합니다.

로그인 화면에서 **세 칸**을 채웁니다.

| 칸 | 넣을 값 |
|---|---|
| Method | **OIDC** 를 고릅니다 |
| **Namespace** | **프로젝트 ID** ← 비우면 로그인이 안 됩니다 |
| Role | 비워 두세요 |

> ⚠ **Namespace 칸이 이 화면의 함정입니다.**
> 비워 두면 로그인이 실패하는데, 오류 메시지가 그 이유를 말해 주지 않습니다.
> 0-1에서 적어 둔 프로젝트 ID를 그대로 넣으세요.

---

## 시크릿 엔진 만들기

OpenBao는 준비되어 있지만 **시크릿 엔진은 아직 없습니다.** 처음 쓰는 사람이 직접 만들어야 합니다.

1. 왼쪽 메뉴 **Secrets Engines**
2. **Enable new engine** 버튼
3. 목록에서 **KV** 선택
4. Version은 **2**
5. Path 칸에 `tutorial` 입력
6. **Enable Engine**

`tutorial` 이 엔진 이름이고, 0-1 템플릿 ②의 **`시크릿 엔진`** 줄과 같은
값입니다. 다른 이름을 쓰고 싶으면 템플릿도 함께 고치세요 — 3단계에서 그 값을
그대로 입력합니다.

---

## 키 저장하기

1. 방금 만든 `tutorial` 을 클릭
2. **Create secret**
3. **Path for this secret** 칸에 `llmchat` 입력
4. 값 입력 영역 오른쪽 위의 **JSON** 토글을 켭니다
5. 편집기 내용을 **전부 지우고**, [0-1에서 채워 둔 ① JSON](01-keys.md)을 그대로
   붙여 넣습니다

```json
{
  "LLM_API_KEY": "sk-여기에-0-1에서-복사한-값-전체",
  "ACCESS_PASSWORD": "아무도-못-맞출-긴-문자열"
}
```

6. **Save**

**이게 전부입니다.** OpenBao에 들어가는 것은 이 둘뿐입니다.

| 키 | 필수 | 무엇 |
|---|---|---|
| `LLM_API_KEY` | ✅ | 0-1에서 발급한 LLM API 키. `sk-` 로 시작 |
| `ACCESS_PASSWORD` | 선택 | 챗봇 접속 비밀번호. 5단계에서 씁니다. 안 쓸 거면 그 줄을 지우세요 |

**대소문자와 밑줄이 정확해야 합니다.** 챗봇이 이 이름을 그대로 찾습니다.
`llm_api_key` 나 `LLM-API-KEY` 는 못 찾습니다.

> JSON 토글이 안 보이면 키/값 칸에 직접 입력해도 똑같습니다.
> 키 `LLM_API_KEY`, 값은 `sk-` 로 시작하는 문자열.

---

## 이 JSON이 챗봇에 어떻게 도착하나

여기 넣은 JSON은 챗봇이 실행될 때 **파일 한 장으로 펼쳐져** 컨테이너 안에
놓입니다.

```
OpenBao의 tutorial/llmchat        컨테이너 안 /vault/secrets/llmchat.env
┌──────────────────────────┐      ┌──────────────────────────────────┐
│ {                        │      │ LLM_API_KEY=sk-xxxxxxxx          │
│   "LLM_API_KEY": "sk-…", │ ───▶ │ ACCESS_PASSWORD=긴문자열          │
│   "ACCESS_PASSWORD": "…" │      │                                  │
│ }                        │      │                                  │
└──────────────────────────┘      └──────────────────────────────────┘
```

**JSON의 키 이름이 그대로 왼쪽에 옵니다.** 그래서 이름을 정확히 써야 하는 것입니다.

1-3에서 이 파일을 직접 열어 보게 됩니다. 그때 위 오른쪽 모양이 나오면 성공입니다.

---

## 그럼 PVC 이름이나 프로젝트 이름은?

**OpenBao에 넣지 않습니다.** 3단계의 차트 값에 적습니다.

당연해 보이지 않을 수 있어서 이유를 적어 둡니다. 값이 **세 종류**이고, 그중 하나는
OpenBao에 넣어도 아예 동작하지 않습니다.

### ① OpenBao에 넣어도 소용없는 값 — 파드를 *만들* 때 필요한 것

| 값 | 어디에 |
|---|---|
| PVC(볼륨) 이름 | 3단계 차트 값 `runway.storage.existingClaim` |
| 시크릿 엔진·시크릿 이름 | 3단계 차트 값 `runway.openbao.*` |
| 호스트명 | 3단계 차트 값 `runway.httpRoute.hostnames` |
| 이미지 주소 | 차트에 이미 들어 있음 |

이 값들은 **파드 스펙을 만드는 재료**입니다. 어느 볼륨을 붙일지, 어느 주소로 열지를
정하는 값이라 파드가 만들어지기 **전에** 필요합니다.

반면 OpenBao의 내용은 파드가 **뜬 뒤에** 파일로 도착합니다. 순서가 반대입니다.

```
   [차트 값]  ──▶ 파드를 만든다 ──▶ 파드가 뜬다 ──▶ [OpenBao 내용]이 파일로 도착
      ▲                                                     │
      └─ PVC 이름은 여기 있어야 합니다                        └─ 여기서는 이미 늦습니다
```

엔진 이름(`tutorial`)이 특히 그렇습니다 — **그 값이 있어야 주입이 시작되므로**
주입되는 내용 안에 넣을 수 없습니다.

### ② 둘 다 되지만, 차트 값을 권합니다

`QDRANT_URL`, `LLM_BASE_URL`, `LLM_MODEL` 같은 것은 앱이 실행 중에 읽으므로 OpenBao에
넣어도 동작합니다. 그래도 차트 값에 두세요 — 비밀이 아닌 값을 OpenBao에 흩어 두면
나중에 "이 설정이 어디 적혀 있지?"를 찾을 때 볼 곳이 두 군데가 됩니다.

### ③ OpenBao에만 넣어야 하는 값 — 비밀

`LLM_API_KEY` 와 `ACCESS_PASSWORD`. **이 둘뿐입니다.**

차트 값에 적으면 그 애플리케이션을 볼 수 있는 사람 모두에게 보입니다.

### 정리

```
OpenBao(0-2)   비밀만        LLM_API_KEY, ACCESS_PASSWORD
차트 값(3-1)   나머지 전부   PVC 이름, Qdrant 주소, 호스트명, 게이트웨이 주소
```

3단계에서 실제로 채우는 값은 네 줄뿐이고, 그때 이 표를 다시 보게 됩니다.

---

## 여기까지 되면 성공

- [ ] OpenBao에 로그인했다 (Namespace 칸에 프로젝트 ID를 넣어서)
- [ ] `tutorial` 시크릿 엔진을 만들었다
- [ ] 그 안에 `llmchat` 을 만들고 `LLM_API_KEY` 를 넣었다
- [ ] 키 이름이 대문자와 밑줄로 정확히 `LLM_API_KEY` 다

OpenBao 안은 이렇게 되어 있습니다.

```
tutorial/            ← 시크릿 엔진 (0-1 템플릿 ②의 '시크릿 엔진')
  └── llmchat        ← 시크릿 (0-1 템플릿 ②의 '시크릿 이름')
        ├── LLM_API_KEY
        └── ACCESS_PASSWORD
```

> 0-1 템플릿 ①의 JSON은 이제 메모에서 지워도 됩니다 — OpenBao에 들어갔으니까요.
> ② 메모는 3단계까지 계속 씁니다.

## 막혔다면

| 이런 화면이 나오면 | 원인 | 이렇게 하세요 |
|---|---|---|
| 로그인이 계속 실패 | Namespace 칸이 비었음 | 프로젝트 ID를 넣으세요 |
| `Secrets Engines` 메뉴가 안 보임 | 보기 전용 권한 | 프로젝트 관리자에게 권한 상향을 요청하세요 |
| 로그인 후 화면이 텅 비어 있음 | 프로젝트의 OpenBao 네임스페이스가 아직 준비 안 됨 | 사용자가 고칠 수 없습니다. 관리자에게 문의하세요 |
| 저장했는데 값이 안 보임 | 정상입니다 | OpenBao는 저장한 값을 다시 보여 주지 않습니다 |
