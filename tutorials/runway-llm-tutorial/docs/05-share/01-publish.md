# 5-1. 팀에 공개하기

지금은 나만 볼 수 있습니다. 팀원들도 쓰게 하는 방법입니다.

걸리는 시간 10분.

---

## 지금 상태

3단계에서 이미 주소를 열고 비밀번호를 걸어 두었습니다. 남은 것은 **팀에 알려 주기
전에 무엇을 아는 상태여야 하는가**입니다.

> ⚠ **애플리케이션 주소 앞에는 로그인이 붙지 않습니다.**
>
> Runway 콘솔에는 로그인이 있지만, 우리가 만든 애플리케이션 주소는 거기 포함되지
> 않습니다. **주소를 아는 사람은 누구나** 이 챗봇 화면까지 옵니다. 그 앞을 막는
> 것은 우리가 건 비밀번호 하나뿐입니다.
>
> - 프로젝트의 AI 사용량을 쓰게 되고
> - 올려 둔 문서를 검색할 수 있습니다
>
> 사내 문서를 올렸다면 가볍게 넘길 일이 아닙니다.

---

## 알려 주기 전에 확인할 것

**1) 비밀번호가 실제로 걸려 있나**

새 시크릿 창(또는 다른 브라우저)으로 주소를 열어 보세요. 비밀번호를 묻지 않고 바로
채팅 화면이 나오면 걸려 있지 않은 것입니다. 애플리케이션 설정에서 확인하세요.

```yaml
runway:
  access:
    passwordRequired: true
```

**2) 비밀번호가 짐작할 수 없는 값인가**

0-2에서 정한 값입니다. `1234` 나 프로젝트 이름 같은 것이면 지금 바꾸세요 — 방법은
아래에 있습니다.

**3) 올려 둔 문서가 공유해도 되는 것인가**

챗봇은 올려 둔 문서를 근거로 답합니다. 비밀번호를 아는 사람은 그 내용을 전부 볼 수
있습니다. 4-2에서 시험용으로 올린 문서가 남아 있다면 챗봇 화면의 문서 목록에서
지우세요.

---

## 비밀번호 바꾸기

OpenBao로 갑니다 (0-2와 같은 경로, Namespace 칸에 프로젝트 ID).

1. `tutorial` 엔진 → `llmchat` 시크릿 → **Create new version**
2. **JSON** 토글을 켜고, 아래처럼 **두 개가 다 들어가게** 만듭니다

```json
{
  "LLM_API_KEY": "sk-기존값-그대로",
  "ACCESS_PASSWORD": "아무도-못-맞출-긴-문자열"
}
```

3. **Save**
4. 애플리케이션 상세 화면에서 **배포**를 다시 누릅니다

> ⚠ **기존 `LLM_API_KEY` 를 빠뜨리지 마세요.**
> 새 버전은 이전 내용을 물려받지 않고 **통째로 대체**합니다. `ACCESS_PASSWORD` 만
> 남기면 챗봇이 키를 잃고 멈춥니다.

> **다시 배포해야 반영됩니다.** OpenBao의 값은 파드가 뜰 때 파일로 전달됩니다.
> 이미 떠 있는 파드는 옛 비밀번호를 그대로 씁니다.

---

## 주소를 아예 닫아 두고 싶다면

혼자 쓰거나 가끔만 쓴다면, 주소를 닫아 두는 것이 가장 안전합니다.

```yaml
runway:
  httpRoute:
    enabled: false
```

이렇게 하면 브라우저로 접근할 수 없게 됩니다. 다시 쓰려면 `true` 로 바꾸고 배포하면
됩니다.

---

## 비밀번호에 대해

공용 비밀번호는 **신원이 아닙니다.** 지나가던 사람의 사용을 막을 뿐, 누가 무엇을
물었는지는 알려 주지 않습니다. 그래도 없는 것보다 훨씬 낫습니다.

팀원에게 주소와 비밀번호를 함께 전달하세요.

---

## 다 끝났습니다

만든 것을 정리하면 이렇습니다.

| 만든 것 | 하는 일 |
|---|---|
| 시크릿 이름 (`tutorial/llmchat`) | 키를 설정 밖에 보관 |
| 볼륨 (`llm-tutorial-data`) | 챗봇의 저장 공간 |
| Code Server | 확인용 작업 화면 |
| Qdrant | 벡터 DB |
| 챗봇 (`llm-chat`) | 대화 + 문서 검색 |

챗봇 안에는 **에이전트**와 **MCP 도구 서버**가 들어 있습니다. 질문을 보고 검색이
필요한지 판단하는 것이 에이전트, 실제로 벡터 DB를 뒤지는 도구를 제공하는 것이 MCP
서버입니다. 따로 설치하지 않았는데도 처음부터 돌고 있었습니다.
