# 1-3. 시크릿 확인

0단계에서 OpenBao에 저장한 키가 **실제로 전달되는지** 눈으로 봅니다.

걸리는 시간 5분 · 명령어 한 줄을 붙여 넣습니다.

---

## 왜 이걸 확인하나

3단계에서 챗봇을 배포할 때, 챗봇도 **똑같은 방식으로** 키를 받아 갑니다.
지금 확인해 두면 나중에 챗봇이 안 될 때 "키 문제인지 아닌지"를 바로 가릴 수
있습니다.

---

## 터미널 열기

1-2에서 만든 Code Server 화면에서:

**위쪽 메뉴 → Terminal → New Terminal**

아래쪽에 검은 창이 열립니다.

---

## 확인하기

아래 한 줄을 복사해서 붙여 넣고 엔터를 누릅니다.

```bash
cat /vault/secrets/llmchat.env
```

이렇게 나오면 성공입니다.

```
LLM_API_KEY=sk-여기에긴문자열
```

0-2에서 `ACCESS_PASSWORD` 도 넣었다면 두 줄이 나옵니다.

```
LLM_API_KEY=sk-여기에긴문자열
ACCESS_PASSWORD=긴문자열
```

**0-2에서 넣은 JSON의 키 이름이 그대로 `=` 왼쪽에 와 있습니다.**
OpenBao의 내용이 파일 한 장으로 펼쳐진 것입니다.

키가 어느 설정 화면에도 적혀 있지 않은데, 실행되는 순간에 OpenBao에서 꺼내져
파일로 전달되었습니다. 3단계의 챗봇도 이 파일을 읽습니다.

---

## 안 나온다면

| 나온 것 | 뜻 | 할 일 |
|---|---|---|
| `No such file or directory` | 키가 전달되지 않음 | Code Server 설정에서 OpenBao 칸 **두 개**가 모두 채워졌는지 확인 |
| 파일은 있는데 이름이 다름 | 엔진 이름이나 시크릿 이름이 다름 | 0-2에서 `tutorial` / `llmchat` 로 만들었는지 확인 |
| `LLM_API_KEY=` 뒤가 비어 있음 | 값을 저장하다 만 것 | OpenBao에서 값을 다시 넣으세요 |

설정을 고쳤다면 애플리케이션 상세 화면에서 **다시 배포**해야 반영됩니다.

디렉터리 자체가 있는지 먼저 보고 싶다면:

```bash
ls -l /vault/secrets/
```

---

## 볼륨도 확인하기 (선택)

1-1에서 만든 볼륨은 Code Server에 붙어 있지 않습니다 — 챗봇이 3단계에서 씁니다.
지금 확인할 것은 없고, 스토리지 목록에서 `Bound` 상태인 것만 보면 됩니다.

---

## 여기까지 되면 성공

- [ ] `cat /vault/secrets/llmchat.env` 가 `sk-` 로 시작하는 값을 보여 준다
- [ ] 스토리지 목록의 `llm-tutorial-data` 가 `Bound` 다

여기까지 왔으면 **가장 헷갈리는 부분은 끝났습니다.** 남은 것은 화면에서 값을 채우는
작업입니다.
