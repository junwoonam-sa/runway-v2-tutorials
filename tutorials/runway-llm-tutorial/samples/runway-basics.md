# Runway 기본 개념 (샘플 문서)

이 파일은 튜토리얼에서 벡터 검색을 시험하기 위한 샘플입니다. 챗봇에게
"프로젝트 ID가 어디에 쓰이냐"처럼 물어보고, `search_documents` 도구가 실제로
불리는지 확인해 보세요.

## 프로젝트

프로젝트 ID 하나가 네 곳에서 같은 이름으로 쓰입니다.

- 쿠버네티스 네임스페이스
- S3 버킷 이름
- OpenBao 네임스페이스
- MLflow 실험 이름의 접두사

그래서 프로젝트 ID를 정할 때는 짧고 소문자와 하이픈만 쓰는 편이 안전합니다.

## 애플리케이션

애플리케이션은 **등록된 Helm 리포지토리의 차트**입니다. git 저장소를 차트로 직접
읽지 않습니다. 소스를 Gitea에 push하는 것과 차트를 패키징해 레지스트리에 올리는 것은
별개의 작업입니다.

생성과 배포도 다릅니다. 생성 폼을 제출하면 설정 행만 만들어지고 상태가
`terminated`로 들어갑니다. 상세 페이지에서 배포 버튼을 눌러야 워크로드가 뜹니다.

## 스토리지

스토리지는 프로젝트 네임스페이스의 PersistentVolumeClaim입니다. 볼륨 ID는 DNS-1123
이름 규칙을 따르고, 크기 단위는 GiB로 고정입니다. 만든 뒤에는 크기만, 그것도
늘리는 방향으로만 바꿀 수 있습니다.

`ceph-block` 스토리지 클래스에는 ReadWriteMany를 쓸 수 없습니다.
